The PulseOps API authenticates with **workspace API keys**. Each key belongs to
a single workspace and carries a scope that determines what it can do.

## Create an API key

1. Open the PulseOps app and go to **Settings → API Keys**.
2. Create a new key and give it a descriptive name.
3. Copy the key — it's shown **once**. Keys are prefixed `po_`.

<Warning>
  Treat API keys like passwords. They grant access to your workspace's
  monitoring data. Store them in a secret manager, never in client-side code or
  version control. If a key leaks, revoke it in **Settings → API Keys** and
  create a new one.
</Warning>

## Authenticate a request

Pass the key in the `x-api-key` header on every request:

```bash
curl https://<your-pulseops-api-host>/api/v1/workspaces/{workspaceId}/monitors \
  -H "x-api-key: po_your_key_here"
```

A missing or invalid key returns `401 Unauthorized`. A key that's valid but
lacks the required scope returns `403 Forbidden`.

## Scopes

<Note>
  **v1 keys are read-only.** They can read monitors, checks, incidents, and
  analytics, and push heartbeat signals — but cannot create, update, or delete
  resources.
</Note>

## Workspace scoping

Most endpoints are scoped to a workspace and take a `workspaceId` path
parameter. A key can only access the workspace it was created in; using it
against another workspace's ID returns `403 Forbidden`. You can find your
workspace ID in the app URL or via the dashboard.
